# Blockers and limits

- **Complete full-runtime build:** 37 AGC tool/test executable targets failed during post-link because Windows Security quarantined generated executables before `objcopy` could process them. Host security settings were not changed. 413 PRX library artifacts were produced, but the full runtime build is not clean.
- **Behavioral evidence:** aggregate missing-function and shader-path counts are not executable requirements. Without a public spec or a synthetic test oracle, implementing guessed semantics would be unsafe.
- **CTest:** The full 6,651-test run completed with 6,492 passes, 122 failures, and 37 skipped tests. Failures include missing/quarantined AGC executables and independent upstream test failures; this is not a green suite. See `TEST_RESULTS.md`.
- **Windows Security:** the system quarantined generated `agc_shader_replay.exe`, so its post-build `objcopy` step failed with `Invalid argument`. This is an observed local block, not confirmed as a false positive; security settings were not changed.
- **Runtime compatibility:** no legally available PS5 homebrew has been supplied or run. GTA VI, game files, and first-frame rendering were not tested.
- **Vulkan runtime:** Three focused tests passed with `VK_LAYER_KHRONOS_validation` explicitly loaded on NVIDIA RTX 4060. This validates those test paths only; it does not establish full rendering, presentation, or successful first-frame output from a homebrew application.
- **Scalar scratch-load shader paths:** `core/shader/recompiler/Translation/src/MemoryInstructions/ScalarBufferInstructions.cpp::TranslationContext::sScratchLoad` still rejects all three decoded forms (`S_SCRATCH_LOAD_DWORD`, `...X2`, `...X4`). The prior implementation was reverted in AnyPS5 history because its scalar/wave lane mapping was not established. The RDNA 2 ISA describes scratch addressing as `flat_scratch.addr + swizzle(offset, threadID)` and says scalar private-space access needs a buffer constant or manual conversion; LLVM documents private storage as lane-interleaved. Existing `core/libs/tests/ScalarScratchLoad.cpp` currently verifies the decoder and asserts that translation throws; it does not provide a semantic oracle. Do not restore the old lowering until lane selection, wave behavior, and out-of-bounds semantics are established and tested. References: [AMD RDNA 2 ISA, scratch addressing and private space](https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna2-shader-instruction-set-architecture.pdf), [LLVM AMDGPU private-memory mapping](https://llvm.org/docs/AMDGPUUsage.html).
- **AGC and service-library exports:** focused audit of the remaining stubs found exports without confirmed ABI prototypes or public behavior contracts; available tests do not exercise those semantics. Implementing these exports from names/NIDs alone would be guesswork. See `third_party/AnyPS5/core/libs/prx/libSceAgcDriver/Export.cpp` and the service-library `*Exports.cpp` inventories. The three AGC shader-preparation tests that had failed in the aggregate run passed when run sequentially (3/3); their aggregate failure remains unexplained.
